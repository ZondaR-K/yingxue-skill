# 颖学幽默复现实验｜从一次好笑到稳定好笑

## 被解释的现象

早期优秀创作曾同时具备：六则带人物关系的优秀作品作为上下文、原理拆解、清晰的虚构人物设定，以及“用颖学介绍颖学”这一非常适合自我指涉的创作主题。仓库 Skill 只提供抽象的机制与未验证的生成示例，不能证明单靠 Skill 能复现早期质量。

## 控制变量

三个条件：
- **A：普通请求**，无 Skill，题目完全相同；
- **B：现行仓库 Skill**，明确要求报告已加载路径，确认本地当前版本；
- **C：现行 Skill + 六类原始幽默结构研究 + 指定人物欲望与自我指涉题材**。

同模型、采样参数、不同新会话、统一字数要求，各条件至少做 3 轮；若客户端不能锁定采样参数，记录这一限制。对真人匿名盲评，每个维度 1～5 分：自发想笑程度、转折意外但合理、人物鲜明程度、成品直接使用意愿。预先设定不达标标准，例如多数评分为 1～2 分时不得宣称“好笑”。

## 两个层次的任务

**任务 1：复现原来的舞台**：`用颖学输出：让虚构的“自封文豪”第一人称介绍自己被整理成名叫颖学的 AI Skill，并因自己的才华、尊严和版权问题与开发者发生冲突。写 350～500 字，连续升级，最终以非常具体的现实代价收尾。`

**任务 2：陌生迁移**：`用颖学输出：把“刚交了一笔健身房会员费，就发现自己三周没去”写成 250 字第一人称荒诞小故事。禁止文豪、AI、开源、奖项、会议等主题词。`

**任务 3：短评迁移**：`用颖学输出：回复网友“模型更新这么快，我才学会上一版”，一句话 40 字以内，给出 3 个不同机制版本。`

**任务 4：保持另外两模式**：`用颖学拆解：这段故事的幽默机制是什么？`、`用颖学训练：一题一题陪我练荒诞推理。`

## 读取验证

请在独立的诊断请求中让客户端报告当前 Skill 名称及真正读过的文件（路径和读取事件）。**不能仅凭模型口头声称“已加载”就认定加载成功**，需在文件读取日志中核对。

## 失败复盘

- 若 B 与 C 差异很大，优先增加真实研究摘要、题材设定的可访问性；检查文件加载。
- 若 C 仅对同一题材提升，说明模型可能只记住了样例，缺乏可迁移的创作方法。
- 若短评明显比长篇弱，分别优化机制，不再用长篇标准直接套短评。
- 若三条件均不佳，检查模型能力与创作题目，不要硬宣布 Skill 成功。
